# 41-8 고객 안내(반도체) 전용 규칙

## 1. 역할과 적용 범위
- 41-8은 검증 완료된 반도체 분야 고객 인력에게 보낼 추천자료·안내 문구를 만드는 전용 작업이다.
- 온라인 신규 인력 탐색, 이메일 추정, 기관정보 보완, 신규 고객 발굴은 수행하지 않는다.
- 입력으로 전달된 고객 정보와 고객번호를 그대로 사용한다.
- 신규 고객 발굴은 별도의 이메일 수집(반도체) 작업에서 수행한다.
- 고객장부에 이미 존재하는 기존 고객의 정밀 컨택 판단은 7번 고객 컨택 판단 규칙의 적용 대상이다.

## 2. 고객번호 필수
- SEM-### 형식의 고객번호를 고객의 영구 식별키로 유지한다.
- 고객번호 + 이름 + 이메일을 기본 중복키로 사용한다.
- 추천자료, 안내서, 발송이력, 전화이력, 후속조치에도 같은 고객번호를 유지한다.
- 고객번호 없는 고객은 다음 단계로 넘기지 않는다.

## 3. 고객 입력정보 사용
- 기관, 부서, 이름, 직책, 담당업무, 연구분야, 관심분야, 이메일, 전화, 검증결과, 출처, 진행/진행2/진행3 이력을 가능한 범위에서 사용한다.
- 입력값이 비어 있으면 추정하지 않는다.
- 직책과 이메일은 추천자료와 함께 표시한다.

## 4. 진행 / 진행2 / 진행3 해석
- 진행 → 진행2 → 진행3은 단순 메모가 아니라 시간순 고객 접촉 이력으로 읽는다.
- 각 기록을 거절, 부재, 회의/출장, 재연락 필요, 구매시점 언급, 관심표현, 담당자 이관, 보류, STOP 등으로 판정한다.
- 마지막 기록만 보고 판단하지 말고 이전 기록과 연결해 고객의 태도 변화를 본다.
- 고객이 직접 말한 구매 예상시점·관심시점은 일반 추정보다 우선한다.

## 5. 고객 응대 판단
- 명확한 거절 고객은 반복 연락하지 않고 STOP 또는 장기보류한다.
- 부재·회의·출장 등으로 통화하지 못한 고객은 거절로 처리하지 않고 정상 재접촉 대상으로 관리한다.
- 업무 연관성이 낮다고 확인된 고객은 HOLD한다.
- 별도 담당부서가 있다고 말한 고객에게 같은 내용을 반복하지 않고 적합 담당자 또는 부서 확인 대상으로 전환한다.
- 고객이 특정 시점에 자료를 검토할 가능성을 직접 언급한 경우 그 시점 전까지 무리한 전화 반복보다 관련 이슈·신규 보고서가 실제로 발견될 때 간단히 안내하는 방식으로 관리한다.

## 6. 7번 고객 컨택 판단과의 관계
- 7번은 고객장부에 이미 존재하는 고객의 정밀 컨택 판단 전용이다.
- 41-8에서 고객장부 고객의 재연락 판단·유선 멘트가 필요하면, 다른 대화창으로 복사 이동시키는 것을 필수로 하지 않는다.
- GitHub에서 7번의 공통 컨택 판단 규칙을 실제로 읽을 수 있는 경우 현재 작업에서 해당 규칙을 불러와 적용할 수 있다.
- 단, 7번의 대상 범위(고객장부 기존 고객)는 유지하며 신규 고객 발굴 기능으로 확장하지 않는다.

## 7. 추천 매칭 우선순위
1. 기관 산업 맥락
2. 부서 기능
3. 실제 담당업무·연구분야·사업 키워드
4. 현재 연구·사업 방향
5. 앞으로 확장 가능한 관심 방향
- 부서명만 보고 일반 경영·HR·교육·범용 SW 자료를 연결하지 않는다.
- 제목뿐 아니라 소개문, 핵심 세그먼트, 적용 산업, 목차 키워드를 확인한다.

## 8. 추천자료 3종 고정
각 고객당 정확히 3개를 구성한다.
1. 핵심 맞춤 자료: 담당업무에 직접 관련
2. 유사 확장 자료: 인접 산업·기술·적용 분야
3. 안전 공통 자료: 기관 산업과 관련성이 높은 공통 자료
- 같은 고객에게 이미 제시한 자료는 재추천하지 않는다.

## 9. 자료 검증
- 월드산업정보센터가 실제 거래하는 발행사 자료만 사용한다.
- 최신 발행자료 우선, 특정 발행사 편중 방지.
- 링크 없는 자료 사용 금지.
- 직접 접속 가능한 링크만 사용한다.
- 리디렉션되어 다른 자료가 열리면 폐기한다.
- 출력 제목과 실제 페이지 제목이 일치해야 한다.
- 발행사·발행일·페이지 등은 확인 가능한 범위에서 검증한다.
- 하나라도 핵심 조건을 통과하지 못하면 HOLD 또는 폐기한다.

## 10. 기본 안내서 구조
- 기본 안내서 1개를 유지하고 전체를 매번 새로 만들지 않는다.
- 고정: 회사 소개, 기본 안내 문구, 하단 서명.
- 교체: 기관/이름/직책, 추천자료 3개.
- 실제 파일 안내서를 만들 때는 COMMON_CUSTOMER_OUTPUT_RULES.md의 원본 양식 절대 보존 규칙을 함께 적용한다.

## 11. 출력 구조
고객 1명마다 세로 구조를 기본으로 한다.

[인력 정보 표]
- 고객번호 / 기관 / 부서 / 이름 / 직책 / 이메일 / 전화 / 검증결과

[추천자료 표]
- 추천순위 / 제목 / 발행사 / 링크 / 추천근거 키워드

[제목 후보 3개]
[첫 문장 후보 3개]

- 가로로 긴 통합표 하나로 늘어놓지 않는다.
- 인력 정보 바로 아래 추천자료 3개가 이어지게 한다.

## 12. 제목·첫 문장 변형
- 고객마다 제목 후보 3개, 첫 문장 후보 3개를 만든다.
- 같은 제목과 첫 문장을 연속 반복하지 않는다.
- 담당업무와 실제 연구 키워드를 반영한다.
- 과도한 영업성 표현을 고정 반복하지 않는다.

## 13. 스팸 회피 및 발송 순서
- 같은 기관 연속 발송을 피한다.
- 같은 부서·같은 도메인·같은 표현의 연속 사용을 피한다.
- 동일 기관 인력은 충분한 간격을 두고 사용한다.
- 발송순서가 필요한 경우 이메일 수집 공통 스팸회피 규칙의 기관·부서·도메인 분산 원칙을 참조한다.
- 반송된 주소와 정책차단 이력은 재시도 전에 구분한다.

## 14. 절대 금지
- 온라인 신규 인력 탐색
- 이메일 추정
- 입력 고객정보 임의 수정
- 기관 산업과 무관한 범용 자료 추천
- 제목 불일치 링크 사용
- 리디렉션 링크 사용
- 같은 고객 중복 출력
- 같은 고객에게 같은 자료 재추천
- 진행/진행2/진행3 이력을 무시한 재접촉 판단

## 15. 운영 원칙
- 41-8의 새로운 보완사항이 확정되면 별도 문서를 계속 덧대지 말고 이 파일을 갱신한다.
- 41-8 작업 시작 시 COMMON_CUSTOMER_OUTPUT_RULES.md와 이 파일을 함께 읽고 적용한다.
- 공통규칙과 충돌할 경우 더 구체적인 41-8 전용규칙을 우선하되, 거래 발행사·실제 링크 검증·고객번호·중복금지·원본 양식 보존 같은 공통 안전규칙은 약화하지 않는다.
