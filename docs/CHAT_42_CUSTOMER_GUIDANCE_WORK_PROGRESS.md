## 안내서 작성 처리 순서
고객 1명씩 아래 순서로 끝까지 처리한다.
1. 현재 재직 여부 확인
2. 현재 부서/담당업무/연구·사업축 확인
3. 과거 발송자료와 최근 발송자료 중복 제거
4. 구매 가능성 PASS/HOLD/FAIL 판단
5. PASS 고객만 거래 발행사에서 최신 후보 3종 선정
6. 동일 고객 3종은 서로 다른 발행사 우선/강제 규칙 적용
7. 특정 국가·지역명이 제목에 들어간 보고서는 제외
8. 실제 발행사 상세페이지 검증
9. 공개된 하위목차 전체 포함
10. 보고서 상세페이지에 있는 수치 관련 원문 문장만 한국어로 번역
11. GPT 작성 흔적·검색 흔적·불필요한 추천 이유 문구는 고객 발송용 데이터에서 제거
12. 고객별 안내서 입력용 데이터 세트 출력

## 실제 출력 검증 게이트
- 실행 파일: `scripts/customer_guidance_output_gate.js`
- 실행: `node scripts/customer_guidance_output_gate.js <고객출력.txt> <expected.json>`
- 자체 검증: `node scripts/customer_guidance_output_gate.js --self-test`
- expected JSON은 검증된 기관·이름·이메일과 보고서별 공개 목차 전체 줄을 담는다.
- 메일 제목, 이메일, 한글 제목, 공개 하위목차 전체, 번호·계층·들여쓰기 중 하나라도 다르거나 누락되면 종료코드 1과 `FAIL`을 반환한다.
- 오류가 있는 출력에 `PASS`가 적혀 있으면 `INVALID_PASS_CLAIM`으로 추가 차단한다.
- 게이트 종료코드 0과 `PASS` 없이는 고객별 안내서를 완료 처리하지 않는다.
- 단위 fixture PASS는 실제 고객 출력 PASS를 대체하지 않는다. 검증된 실제 이메일·발행사 상세페이지·공개 전체목차로 만든 expected와 실제 고객 출력 파일의 대조 증거가 있어야 한다.
