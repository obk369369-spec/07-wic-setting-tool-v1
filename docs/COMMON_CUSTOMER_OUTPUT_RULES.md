# WIC 공통 고객 출력·추천·안내서 생성 규칙

## 적용 범위
모든 이메일 수집 대화창, 고객 추천 대화창, 안내서 생성 작업, 관련 자동화 도구에 공통 적용한다.

## 고객번호 필수 규칙
- 모든 고객 인력 출력에는 고객번호를 반드시 함께 표시한다.
- 중간 단계에서 고객번호가 누락되었더라도 최종 출력 전에 반드시 복원·확인한다.
- 고객번호 없이 고객 정보를 출력하거나 다음 단계로 전달하지 않는다.
- 고객번호는 고객 DB, 추천자료 표, 중간 안내서 작업 대상, 최종 안내서 작업 대상, 발송이력에서 동일한 식별자로 유지한다.
- 이름·이메일이 같아도 고객번호 기준으로 중복 여부를 다시 확인한다.

## 추천 보고서 발행사 다양성 규칙
- 추천 자료는 특정 2~3개 발행사에 편중하지 않는다.
- 월드산업정보센터가 실제 거래하는 전체 발행사 풀을 대상으로 후보를 찾는다.
- 고객의 기관 산업을 1차 축, 부서 기능을 2차 축, 실제 담당업무·연구·사업 방향을 3차 축으로 매칭한다.
- 부서가 홍보·준법·대외협력 등 비기술 부서여도 기관 자체가 방산 기관이면 기관의 방산 산업 맥락을 우선 반영한다.
- 최근 발행 자료를 우선한다.
- 같은 고객에게 3종 추천 시 가능한 범위에서 발행사를 분산한다.
- 실제 거래 발행사 여부가 확인되지 않으면 추천 후보에서 제외하거나 HOLD 처리한다.

## 실제 보고서 데이터 검증 규칙
- 임의 보고서명, 임의 링크, 임의 목차, 임의 발행정보 생성 금지.
- 실제 발행사 페이지에서 확인되는 자료만 사용한다.
- 출력 제목과 링크 페이지의 실제 제목이 일치해야 한다.
- 발행사, 발행일, 페이지, 가격, 링크, 목차는 확인 가능한 값만 사용한다.
- 확인되지 않는 값은 추정하지 않고 확인 필요/HOLD로 처리한다.
- 링크 오류, 제목 불일치, 리디렉션으로 다른 자료가 열리는 경우 폐기한다.
- 사용자가 결과를 다시 수동 검증해야만 쓸 수 있는 상태는 PASS가 아니다.

## 중복 방지 규칙
- 고객번호 + 이름 + 이메일을 기본 중복키로 사용한다.
- 이미 처리·발송한 고객은 발송이력을 먼저 확인한다.
- 같은 고객에게 같은 보고서를 다시 추천하거나 발송하지 않는다.
- 분야별 대화창이 달라도 공통 중복기록을 기준으로 차단한다.

## 안내서 원본 양식 절대 보존 규칙
- 사용자가 제공한 월드산업정보센터 실제 안내서 원본 양식을 유일한 기준본으로 사용한다.
- 새 HTML, 새 표, 새 문단 구조, 새 CSS, 새 inline-block 구조를 임의로 만들지 않는다.
- 원본의 표 구조, 행, 셀, span, 문단, 테두리, 글꼴, 크기, 정렬, 폭, 높이, 페이지 나눔, Word 전용 태그, 문자 인코딩을 그대로 유지한다.
- 안내서를 만들 때는 원본의 기존 데이터 위치에 값만 넣는다. 구조를 재조립하거나 보기 좋게 만든다는 이유로 다시 구성하지 않는다.
- 사용자가 제공한 원본의 데이터 슬롯에만 제목, 한글제목, 발행사, 페이지, 정가, 발행일, PDF 표시, 공급가격, 링크, 중간 콘텐츠 또는 목차를 주입한다.
- 원본에 없는 태그나 레이아웃 구조를 추가해야 한다면 자동으로 진행하지 말고 HOLD한다.
- 파일 생성 성공, 문자열 존재, 인코딩 검사만으로 PASS 처리하지 않는다.
- 실제 브라우저 또는 Word에서 렌더된 화면이 원본 양식과 같은 형태인지 검증한 후에만 전달한다.
- 렌더 검증을 실제로 수행하지 못한 경우 '검증 완료'라고 표현하지 않는다.
- 깨짐, 상단 정렬 붕괴, 데이터 좌측 쏠림, 셀 폭 변형, 제목 위치 변경, 테두리 변화가 하나라도 있으면 FAIL로 처리하고 사용자에게 보내지 않는다.

## 중간 안내서 규칙
- 중간 안내서는 예비 고객용이다.
- 월드산업정보센터 신간자료안내 원본 양식을 그대로 사용한다.
- 제목, 한글제목, 도서정보, 실제 링크는 최종 안내서와 동일한 검증 데이터를 재사용한다.
- 목차는 넣지 않는다.
- 목차 대신 발행사 공식 페이지에서 실제 확인되는 공개 콘텐츠를 짧게 넣는다.
- 사용 가능한 예: Report Overview, Key Highlights, Market Segmentation, 적용분야, 주요 기업, 시장전망 등.
- 발행사에 존재하지 않는 설명을 임의 생성하지 않는다.
- 중간 안내서 하단이 빈약해 보인다는 이유로 임의 홍보문이나 추정 콘텐츠를 넣지 않는다.

## 최종 안내서 규칙
- 최종 안내서는 확정된 보고서 정보를 월드산업정보센터 원본 안내서에 반영한 발송용 문서다.
- 하단에는 실제 발행사 원문에서 검증된 목차를 넣는다.
- 목차는 원문 계층을 유지한다.
- 상위 목차는 가장 왼쪽, 하위 목차는 상위보다 오른쪽으로 들여쓰기, 하하위 목차는 하위보다 더 오른쪽으로 들여쓰기한다.
- 모든 목차를 같은 왼쪽 위치에 붙이는 것을 금지한다.
- 목차를 임의로 평면화하거나 상위·하위 계층을 섞지 않는다.
- 안내서 목차 칸의 공간에 맞게 계층 깊이를 조절한다. 단순히 뒤를 잘라내지 않는다.
- 상위 목차만으로 공간이 차면 상위 목차 중심으로 구성하고, 공간이 남으면 하위 목차, 더 남으면 하하위 목차 일부까지 포함한다.
- 수동 안내서 수준으로 대분류·중분류·하위항목·줄바꿈·들여쓰기·공백비율을 검증한다.
- 목차 칸이 지나치게 비거나, 박스 밖으로 넘치거나, 들여쓰기가 틀리면 HOLD 또는 FAIL이다.

## 상단 도서정보 고정 규칙
- 상단은 원본 양식 그대로 유지한다.
- 영문 제목과 한글 제목의 위치·크기·정렬을 변경하지 않는다.
- 도서정보는 원본의 좌/중/우 배치를 유지한다.
- 발행사·발행일은 왼쪽, 페이지·PDF는 가운데, 정가·공급가격은 오른쪽이라는 기존 원본 배치를 임의로 바꾸지 않는다.
- 데이터가 길어도 새 레이아웃을 만들지 않는다. 원본 슬롯에 들어갈 수 있는 표현으로만 조정한다.

## 출력 전 강제 검증 순서
1. 고객번호·중복 여부 확인
2. 거래 발행사 전체 풀 기준 후보 탐색
3. 고객 연구·사업 방향 매칭
4. 최근 발행 우선 및 발행사 분산 확인
5. 보고서 제목 = 링크 페이지 제목 일치 확인
6. 발행사·발행일·페이지·가격·링크 확인
7. 중간 안내서는 발행사 공개 콘텐츠 확인 / 최종 안내서는 실제 목차 확인
8. 원본 양식 데이터 슬롯만 교체했는지 Git diff 또는 구조 비교
9. 실제 렌더 화면에서 상단·링크·하단·테두리·정렬 확인
10. 최종 안내서 목차 계층 들여쓰기 확인
11. 모든 조건 통과 후에만 PASS 및 사용자 전달

## 실패 반복 방지
- 사용자가 한 번 지적한 실패 유형은 이후 동일 작업의 금지 규칙으로 즉시 반영한다.
- 실패 파일을 조금 수정해 계속 덧대는 방식보다 원본 기준본으로 다시 시작한다.
- 이전 실패 결과물을 새 기준본으로 사용하지 않는다.
- 사용자에게 같은 오류를 반복 확인시키지 않는다.

## 운영 원칙
- 이 문서는 공통 기준 파일이며, 이후 규칙 보완 시 새 문서를 덧대지 말고 이 파일을 갱신한다.
- 안내서 관련 대화창이나 도구는 작업 시작 전 이 공통 규칙을 먼저 읽고 적용해야 한다.
