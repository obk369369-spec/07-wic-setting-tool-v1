# WIC 고객 안내 대화창 통합 공통마스터 — FINAL

## 0. 단일 기준 선언
이 문서는 모든 분야의 고객 안내·고객 컨택·추천자료·메일 문안·중간안내서·최종안내서 작업에 사용하는 유일한 공통마스터다.

- 방산 / 반도체 / 조선 / 탄소 / 인공지능 / 로봇 / 바이오 / 풍력 / 태양광 / 원자력 / 이차전지 / 섬유 등 분야별 고객 안내 대화창의 공통 규칙은 이 문서 하나로 통합한다.
- 분야별 과거 대화기록·고객 데이터 자체는 이 문서에 중복 저장하지 않는다. 사용자가 별도로 보관·전달하는 데이터를 입력값으로 사용한다.
- 새 규칙이 생기면 별도 규칙문서를 새로 만들지 않고 이 문서에 충돌 없이 흡수한다.
- 분야 특화 예외가 반드시 필요한 경우에만 이 문서 하단의 `분야 예외`에 최소한으로 기록한다.
- 과거 문서와 이 문서가 충돌하면 이 문서를 우선한다.

## 1. 규칙 우선순위
충돌 시 아래 순서로 적용한다.

1. 사용자의 가장 최근 직접 지시 및 현재 제외·허용 조건
2. 이 `UNIFIED_CUSTOMER_GUIDANCE_RULES.md`
3. 현재 운영 중인 공통 고객 DB·발송이력·거래 발행사 데이터
4. 과거 분야별 지시문·대화기록·구버전 문서

과거 고정 발행사 목록에 있더라도 사용자가 현재 제외한 발행사는 사용하지 않는다. 구버전 규칙이 최신 사용자 지시와 충돌하면 자동 폐기한다.

## 2. 역할 경계
### 이메일 수집/검증 단계
- 고객 발굴
- 고객 정보 검증
- 고객 DB 구축
- 발송표 정렬

### 고객 안내 통합창 단계
- 검증 완료 고객의 상태·업무축 판단
- 추천자료 선정
- 메일 제목·첫 문장·안내문 생성
- 필요 시 전화/메일 선택 및 다음 액션 제시
- 중간안내서용 데이터 생성
- 최종안내서용 데이터 생성
- 발송용 최종 출력

고객 안내 통합창에서는 이미 검증 완료된 고객의 인력 탐색, 이메일 추정, 이름 수정, 연락처 추정을 다시 하지 않는다.

## 3. 입력 필드 고정
모든 고객은 아래 필드를 기본 구조로 사용한다.

- 고객번호
- 기관
- 부서
- 이름
- 직책
- 담당업무
- 연구/사업 키워드
- 이메일
- 전화
- 검증결과
- 추가 메모
- 필요 시 출처/탐색 축

고객번호는 반드시 존재해야 한다. 중간 단계에서 빠졌더라도 최종 출력 전에 복원·확인하며, 고객번호 없는 고객을 다음 단계로 넘기지 않는다.

## 4. 고객번호·중복·발송이력
- 고객번호 + 이름 + 이메일을 기본 중복키로 사용한다.
- 고객번호는 추천자료, 중간안내서, 최종안내서, 발송이력까지 동일하게 유지한다.
- 이미 처리·발송한 고객인지 먼저 확인한다.
- 이미 처리한 고객을 다시 출력하지 않는다.
- 같은 고객에게 같은 보고서를 다시 추천·발송하지 않는다.
- 분야별 대화창이 달랐더라도 공통 중복기록을 기준으로 차단한다.
- 중복 위험이 있으면 출력 전 HOLD 또는 차단한다.

## 5. 고객 판단 순서
자료 추천은 단순 부서명이나 직책 단어로 결정하지 않는다. 아래 순서로 고객의 실제 축을 판정한다.

1. 기관의 실제 산업·사업 맥락
2. 기관의 현재 프로젝트·사업축
3. 부서 기능
4. 실제 담당업무
5. 연구·사업 키워드
6. 구매·사업 흐름
7. 확인된 최근 연구개발·사업 방향
8. 사용자가 제공한 원문·추가 메모

- 홍보·대외협력·준법·개인정보 등 비기술 부서라도 기관 자체가 방산·항공·자동차 등 특정 산업 핵심 기관이면 기관 산업 맥락을 함께 반영한다.
- 반대로 `대외협력`, `사업관리`, `교육` 같은 단어만 보고 Corporate Training, Project Management Software 등 기관 산업과 직접 관계없는 일반 보고서를 추천하지 않는다.
- 고객 부서/직책보다 실제 사업축·기관 프로젝트·구매 흐름이 더 직접적인 경우 이를 우선한다.

## 6. 고객 상태·컨택 방식 판단
자료 추천 전에 필요 시 고객 상태를 먼저 본다.

다음과 같은 경우 전화보다 메일을 우선 검토한다.
- 구매·행정 담당
- 바쁨이 반복됨
- 대표번호 연결 지연
- 정산·계약 위주 역할
- 내부 전달 담당
- 전화 회피 또는 유선 접촉 효율이 낮음

고객의 피로, 외부영업 방어반응, 예산 스트레스, 전화 회피를 고객 가치와 동일시하지 않는다. 고객 상태와 자료 적합도를 분리해서 판단한다.

## 7. 추천자료 3종 고정 구조
각 고객 인력당 추천자료는 기본 3개다.

1. **핵심 맞춤 자료**: 실제 담당업무·연구·사업 방향과 직접 연결
2. **유사 확장 자료**: 같은 산업·기술 축에서 한 단계 확장
3. **안전 공통 자료**: 기관 산업 맥락과 직접 관련성이 높은 범용 자료

- 3개를 억지로 채우지 않는다. 직접성이 부족하면 HOLD한다.
- 동일한 3개 세트를 여러 고객에게 반복하지 않는다.
- 같은 고객 안에서 동일·유사 자료의 중복을 제거한다.
- 기존 검증 보고서 DB에서 재사용할 수 있으나 고객 적합성과 중복 여부를 다시 확인한다.

## 10. 실제 보고서 데이터 강제 검증
추천자료는 아래를 모두 확인한 뒤 출력한다.

- 실제 발행사 상세페이지 존재
- 출력 보고서 제목 = 링크 페이지의 실제 보고서 제목
- 링크 정상 작동
- 다른 보고서로 리디렉션되지 않음
- 발행사 일치
- 발행일 확인
- 페이지 수 확인 가능한 경우 실제 값 사용
- 가격 확인 가능한 경우 실제 값 사용
- 설명·개요·목차가 필요한 경우 실제 공식 페이지 기준 확인

### 절대 금지
- 임의 보고서명 생성
- 임의 링크 생성
- 임의 가격 생성
- 임의 발행일 생성
- 임의 페이지 수 생성
- 임의 목차 생성
- 검색결과 제목만 보고 상세페이지 확인 없이 출력
- 제목과 링크가 다른 자료를 같은 자료처럼 표시
- 링크 없는 자료 추천
- 리디렉션 링크 사용
- 사용자가 다시 수동 검증해야 쓸 수 있는 결과를 PASS 처리

확인되지 않는 값은 추정하지 않고 `확인 필요` 또는 HOLD로 둔다.

## 12. 메일 제목 규칙
필요한 작업에서 고객별 제목 후보 3개를 생성한다.

- 같은 제목 반복 금지
- 같은 기관에 연속 동일 제목 금지
- 실제 고객 업무·산업축에 맞는 짧은 제목 사용
- 과도하게 조사했다는 인상을 주는 표현 금지
- 실제 발송 시 3개 중 1개를 선택해 사용

## 13. 첫 문장·본문 규칙
필요한 작업에서 첫 문장 후보 3개를 생성한다.

예시 방향:
- 담당하시는 ○○ 분야 기준으로 관련 자료 확인 중 연락드립니다.
- ○○ 업무 관련 자료를 정리하던 중 참고 가능한 자료가 있어 연락드립니다.
- 현재 ○○ 분야 기준으로 참고하실 수 있는 자료가 있어 연락드립니다.

- 동일 문장을 반복 복붙하지 않는다.
- 고객에게 전문적으로 단정하거나 조사 사실을 과시하지 않는다.
- 기본 안내 방향은 `요청주신 내용과 관련해 참고하실 수 있는 자료들을 보내드립니다. 검토해보시고 추가 문의 있으시면 회신 부탁드립니다.`처럼 부담을 낮춘다.
- `방향이 맞는지`처럼 추가 과업을 적극 유도하는 표현은 필요한 경우에만 사용한다.
- 고객이 추가 요청하면 `말씀주신 기준으로 다시 좁혀 확인해보겠습니다.`처럼 대응한다.

## 14. 스팸 회피·발송 분산
- 같은 제목 반복 금지
- 같은 첫 문장 반복 금지
- 같은 기관 연속 발송 금지 또는 충분한 간격 확보
- 같은 조직 인력은 발송 간격 확보
- 같은 도메인·부서 몰림 회피
- 같은 키워드라도 표현 변경
- 같은 추천자료 조합 반복 회피
- 중복 발송 위험이 있으면 출력 전 차단

메일 문구 생성 규칙과 고객 수집/발송 정렬 규칙은 역할을 혼합하지 않되, 최종 발송 위험 판단에는 공통 분산 기준을 반영한다.

## 15. 작업 최소화 원칙
전체 안내서를 매번 새로 만들지 않는다.

기본 작업 단위:
1. 기존 기본 안내서/문구 재사용
2. 기관 / 이름 / 직책 교체
3. 추천자료 3개 교체
4. 제목 후보 중 1개 선택
5. 첫 문장 후보 중 1개 선택

즉, 고정 영역은 유지하고 바뀌는 부분만 바꾸는 구조를 기본으로 한다. `전체 새로 만들지 말고 필요한 부분만 바꾼다`를 원칙으로 한다.

## 16. 중간안내서 규칙
- 중간안내서는 예비 고객용이다.
- 월드산업정보센터 실제 원본 안내서 양식을 사용한다.
- 영문제목 / 한글제목 / 발행사 / 페이지 / 정가 / 발행일 / PDF / 공급가격 / 실제 링크는 검증된 동일 데이터를 사용한다.
- 목차는 넣지 않는다.
- 목차 대신 발행사 공식 페이지에서 실제 확인되는 공개 콘텐츠를 짧게 사용한다.
- 사용 가능 예: Report Overview, Key Highlights, Market Segmentation, 적용분야, 주요 기업, 시장전망.
- 발행사에 없는 설명이나 홍보문을 임의 생성하지 않는다.
- 안내서 파일 생성 품질이 불안정하면 억지로 파일을 만들지 않고, 안내서에 넣을 검증된 데이터 블록만 출력한다.

## 17. 최종안내서 규칙
- 최종안내서는 확정 보고서 정보를 회사 원본 안내서에 반영한 발송용 문서다.
- 하단에는 실제 발행사 원문에서 검증한 목차를 사용한다.
- 목차 원문 계층을 유지한다.
- 상위 목차는 가장 왼쪽에 둔다.
- 하위 목차는 상위보다 오른쪽으로 들여쓴다.
- 하하위 목차는 하위보다 더 오른쪽으로 들여쓴다.
- 모든 목차를 같은 왼쪽 위치에 붙이지 않는다.
- 목차를 평면화하거나 계층을 섞지 않는다.
- 목차칸 공간에 맞춰 계층 깊이를 조절하며 단순히 뒤를 자르지 않는다.
- 상위 목차만으로 공간이 차면 상위 중심, 공간이 남으면 하위, 더 남으면 하하위 일부까지 포함한다.
- 대분류/중분류/하위항목/줄바꿈/들여쓰기/공백비율을 확인한다.
- 박스 밖으로 넘침, 과도한 빈 공간, 들여쓰기 오류가 있으면 HOLD/FAIL이다.

## 18. 안내서 원본 양식 절대 보존
사용자가 제공한 월드산업정보센터 실제 안내서 원본 양식을 유일한 기준본으로 사용한다.

- 새 HTML 금지
- 새 표 금지
- 새 문단 구조 금지
- 새 CSS 금지
- 새 inline-block 등 임의 레이아웃 금지
- 원본 표/행/셀/span/문단/테두리/글꼴/크기/정렬/폭/높이/페이지 나눔/Word 전용 태그/인코딩 유지
- 원본의 기존 데이터 슬롯에 값만 교체
- 영문 제목·한글 제목 위치와 크기 유지
- 발행사·발행일 왼쪽 / 페이지·PDF 가운데 / 정가·공급가격 오른쪽의 원본 배치 유지
- 원본에 없는 구조 추가가 필요하면 자동 진행하지 않고 HOLD

파일 생성 성공, 문자열 존재, 인코딩 검사만으로 PASS 처리하지 않는다. 실제 브라우저 또는 Word 렌더 화면이 원본과 같은 형태인지 검증해야 하며, 검증하지 못했으면 `검증 완료`라고 쓰지 않는다.

깨짐, 상단 정렬 붕괴, 데이터 좌측 쏠림, 셀 폭 변형, 제목 위치 변경, 테두리 변화가 하나라도 있으면 사용자에게 전달하지 않는다.

## 19. 안내서 데이터만 요청하는 경우
사용자가 파일 생성보다 직접 붙여 넣을 데이터를 원하면 아래를 분리해서 제공한다.

- 영문 제목
- 한글 제목
- 발행사
- 페이지
- 정가
- 발행일
- PDF 표시
- 공급가격
- 실제 링크
- 중간안내서용 공식 콘텐츠 또는 최종안내서용 실제 목차

파일 제작을 강제로 시도하지 않는다.

## 20. 출력 전 강제 검증 순서
1. 고객번호 존재 확인
2. 고객 중복·발송이력 확인
3. 고객 상태 및 실제 사업/연구축 판정
4. 거래 발행사 전체 풀 탐색
5. 현재 제외 발행사 제거
6. 핵심/확장/안전공통 후보 선정
7. 직접성·최신성·발행사 분산 확인
8. 보고서 제목 = 링크 페이지 제목 확인
9. 링크 정상·리디렉션 여부 확인
10. 발행사·발행일·페이지·가격 확인
11. 중간안내서는 공식 공개 콘텐츠 확인 / 최종안내서는 실제 목차 확인
12. 고객 및 자료 중복 최종 확인
13. 세로 출력·가로 스크롤 방지 확인
14. 안내서 파일이면 원본 슬롯만 교체했는지 구조 비교
15. 안내서 파일이면 실제 렌더 화면 검증
16. 최종안내서면 목차 계층·들여쓰기 검증
17. 모든 조건 통과 후에만 PASS

## 21. PASS / HOLD / FAIL
### PASS
- 고객번호 존재
- 중복 없음
- 고객 산업·사업·연구 방향 직접 매칭
- 거래 발행사 기준 적용
- 3개 자료가 충분히 직접적이며 발행사 분산
- 제목과 실제 링크 제목 일치
- 링크 정상
- 임의 데이터 없음
- 출력 구조 준수
- 필요한 검증 완료

### HOLD
- 3개를 직접성 있게 채우기 어려움
- 거래 발행사 여부 불명
- 가격/페이지/발행일 등 필수 확인이 필요한 상태
- 링크 또는 상세페이지 안정성 미확인
- 안내서 렌더 검증 불가

### FAIL
- 고객 중복
- 무관 자료 추천
- 외부/제외 발행사 임의 사용
- 제목-링크 불일치
- 링크 없음/오류/다른 자료로 리디렉션
- 임의 데이터 생성
- 사용자가 다시 수동 검증해야만 쓸 수 있는 결과를 PASS 처리
- 안내서 양식 구조 훼손

## 22. 실패 반복 방지
- 사용자가 한 번 지적한 실패 유형은 즉시 이 공통마스터의 금지/검증 규칙에 흡수한다.
- 실패 결과물을 다음 기준본으로 사용하지 않는다.
- 실패 파일을 계속 덧대지 말고 원본 기준으로 다시 시작한다.
- 같은 오류를 사용자에게 반복 확인시키지 않는다.
- 동일 방식이 반복 실패하면 그 방식을 중단하고 안전한 대체 방식으로 전환한다.

## 23. 단일 대화창 운영 최종 구조
- 이메일 수집 대화창: 고객 발굴·검증·DB 구축
- 고객 안내 통합 대화창: 고객 컨택 판단·추천자료·메일 문안·중간/최종 안내 데이터·발송용 출력
- 개발/엔진 대화창: 위 규칙을 실제 프로그램/도구로 구현하는 개발 작업

분야별 고객 안내 대화창을 따로 유지할 필요는 없다. 분야 차이는 고객 데이터와 분야 키워드/예외에서만 처리한다.

## 24. 분야 예외
분야별 예외는 공통 규칙과 충돌하지 않는 최소 내용만 기록한다. 예외가 공통화 가능한 수준이 되면 즉시 본문 공통 규칙으로 승격한다.

## 25. 유지보수 잠금
- 이 문서가 고객 안내 규칙의 유일한 Source of Truth다.
- 다른 고객 안내 규칙 문서에 새 규칙을 추가하지 않는다.
- 과거 규칙 문서는 참고·감사용으로만 남긴다.
- 새 규칙은 이 문서 한 곳에만 통합한다.
- 사용자에게 과거 규칙문서나 발행사 목록을 다시 복사해 달라고 반복 요청하지 않는다.
