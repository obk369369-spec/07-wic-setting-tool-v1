## 2026-08-19 실행 오류 및 재발 방지 강제 게이트
이번 실제 고객 안내 출력에서 중앙마스터에 이미 존재하는 규칙을 실행 단계에서 누락한 오류가 확인되었다. 아래는 신규 규칙 생성이 아니라 중앙마스터 §12~§16, §21~§23의 실행 강제 체크포인트다.

### 확인된 실행 오류
- 고객별 출력 맨 앞의 `메일 제목` 누락.
- 고객명과 검증된 이메일 주소를 첫 블록에 함께 표시하지 않음.
- 보고서별 한글 제목 누락.
- 최종안내서용 목차를 발행사 상세페이지의 실제 공개 목차 전체 구조로 뽑지 않고 몇 개 세그먼트만 요약.
- 목차의 상위→하위→하하위 계층/번호/들여쓰기 미준수.
- 중앙마스터 규칙이 있었음에도 실행 결과가 이를 따르지 않았는데 PASS형 결과처럼 제시함.

### 앞으로 고객 1명당 출력 전 반드시 확인
1. 첫 줄 `메일 제목: [해외시장자료 안내] {기관} {이름}님` 존재.
2. 둘째 줄 `이메일 주소: {검증된 실제 이메일}` 존재.
3. 고객명·기관·부서·직책·담당업무는 검증값만 사용.
4. 추천자료 1→2→3 순서 유지.
5. 각 자료마다 `영문 제목 → 한글 제목 → 도서정보 → 순수 상세페이지 링크 → 실제 공개 콘텐츠/목차` 순서 유지.
6. 한글 제목은 고객 안내용으로 반드시 표시하되, 공식 한글 제목이 없으면 `한글 제목(참고 번역)`으로 명확히 분리한다. 공식 제목처럼 위장하지 않는다.
7. 최종안내서용 목차는 해당 발행사 상세페이지에서 공개된 목차만 사용한다.
8. 목차가 공개돼 있으면 대목차만 추려 요약하지 않고 공개된 중목차·소목차까지 모두 포함한다.
9. 원문 계층과 번호 순서를 보존하고 하위목차는 들여쓰기한다.
10. 실제 상세페이지에 공개 목차가 충분하지 않으면 임의 생성하지 않고 `목차 확인 필요/HOLD`로 처리한다.
11. 위 항목 중 하나라도 빠지면 해당 고객 안내서는 PASS/완료 금지.
12. 사용자가 한 번 지적한 위 실패유형은 다시 사용자에게 설명·확인시키지 않고 자동 점검한다.
